# ИС управления обратной связью клиентов банка

Здесь лежит архитектурное описание информационной системы в нотации C4 Model. Репозиторий ведёт команда курсового проекта и лабораторных работ по дисциплине «Информационные системы и технологии» (МГТУ «СТАНКИН», направление 09.03.03 «Прикладная информатика»). Диаграммы написаны кодом в PlantUML с библиотекой C4-PlantUML.

Система собирает отзывы клиентов банка и автоматически определяет их темы и тональность. Если отзыв негативный и касается значимой темы, система заводит обращение, назначает его владельцу продукта и следит за сроком реакции; при просрочке обращение передаётся руководителю направления. По накопленным данным система строит аналитику настроений и отчёты о времени реакции. За основу команда взяла кейс Газпромбанк.Тех «Сервис для отслеживания динамики клиентских настроений» с хакатона «Лидеры цифровой трансформации» 2025 года и расширила его до системы управления.

## Правила оформления диаграмм

Часть правил взята из раздела 4.4 методических указаний к лабораторным работам, остальные команда приняла сама по итогам ревью.

1. Связи задаются только макросом `Rel(от, кому, "описание", "протокол")`. Макросы `Rel_D`, `Rel_R`, `Rel_L`, `Rel_U` и `BiRel` запрещены: раскладку рассчитывает движок.
2. У каждой связи есть описание бизнес-действия и технический протокол: HTTPS / JSON, SQL / TCP, AMQP, SMTP / TLS, APNs / FCM и т. п. «Email» и «push» протоколами не являются: для почты указывается SMTP / TLS, для push-уведомлений APNs / FCM.
3. Одна стрелка описывает одно действие. Если между двумя элементами несколько разных задач, стрелок тоже несколько.
4. Стрелка направлена от инициатора сетевого соединения. Если данные при этом идут обратно, например при чтении из базы, это указано в описании.
5. Цвета, шрифты, `skinparam`, `LAYOUT_WITH_LEGEND()` и другие настройки оформления есть только в общих файлах тимлида. Личные файлы содержат одну структуру.
6. Порты на диаграмме контейнеров не указываются, они появятся на диаграмме развёртывания в ЛР № 4.
7. Личная диаграмма уточняет общую: каждая её связь соответствует связи общей диаграммы между теми же элементами и с тем же протоколом.

## Проверка перед Pull Request

Скрипт сравнивает каждую личную диаграмму с общей: элементы, описания, пары связей и протоколы, а также ищет запрещённые макросы и оформление в личных файлах.

```bash
python check_consistency.py
```

При расхождениях скрипт перечисляет их и завершается с кодом 1, поэтому в ЛР № 5 его можно подключить в CI. Пока скрипт находит ошибки, тимлид не сливает Pull Request.

## Как отрисовать диаграммы

Методические указания рекомендуют локальный стек: Visual Studio Code, расширение PlantUML, Graphviz и Docker-контейнер PlantUML Server, чтобы код архитектуры не уходил на публичные серверы.

1. Открыть файл `.puml` в VS Code.
2. Нажать Alt+D, откроется предпросмотр.
3. Экспортировать изображение в PNG или SVG и сохранить в `docs/images/` с тем же именем, что у исходного файла.

## Порядок работы в Git

Правила защиты ветки запрещают прямые коммиты в `main`: изменения попадают туда только через Pull Request, который одобрил тимлид.

Перед первым коммитом проверьте, что почта в Git совпадает с почтой аккаунта GitHub; иначе коммиты не засчитаются вам в статистике участников.

```bash
git config user.name "Имя Фамилия"
git config user.email "почта-аккаунта-github@example.com"
```

Работа над лабораторной:

```bash
git checkout main && git pull
git checkout -b feature/<роль>-lab1          # например, feature/ml-lab1
# правки своих файлов в src/individual/ и reports/lab1/
python check_consistency.py
git add src/individual/<роль>_*.puml docs/images/<роль>_* reports/lab1/<свой отчёт>
git commit -m "lab1: <роль> личные диаграммы L1 и L2"
git push -u origin feature/<роль>-lab1
```

Затем откройте на GitHub Pull Request в `main`. Тимлид проверяет его по правилам выше, оставляет комментарии и сливает после исправлений. Свои файлы каждый участник коммитит сам и со своего аккаунта. Преподаватель смотрит, как коммиты распределены по участникам и по времени, и штрафует команду, если всё залил один человек.

## Отчётность по лабораторным работам

К каждой лабораторной работе преподаватель требует сдать:

1. Файл отчёта (PDF или Word) с текстовым описанием, таблицами и итоговыми графическими схемами.
2. Исходные файлы диаграмм в формате `.puml`.
3. Ссылка на этот репозиторий. Репозиторий должен быть доступен для проверки истории коммитов всех участников.
