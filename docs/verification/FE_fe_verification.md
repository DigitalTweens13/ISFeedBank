## 6. На что обратить внимание в этой роли

- Веб-панель исполняется в браузере сотрудника, статику ей отдаёт Nginx; вход выполняется через `bank_iam` по OIDC, сессию держит BFF-слой с cookie и защитой CSRF.
- Мобильное приложение получает push через `notify_service` (APNs / FCM), напрямую брокер и базу данных не вызывает.
- Клиенты обращаются только к Backend API через Nginx (HTTPS, 443); ни к базе данных, ни к брокеру они не подключаются.
- Названия компонентов L3 и классов L4 берутся из глоссария (`web_*`, `mob_*`) и из `src/individual/FEDiagramsCode/fe_l3.puml`.

## 8. Раздельные отчёты по веб-панели и мобильному приложению

Диаграммы ЛР № 4 у роли общие для двух контейнеров. Если отчёты пишутся отдельно, делите так:

| Контейнер | Шаги динамики | Узлы развёртывания | Особенность |
|---|---|---|---|
| Веб-панель (`web_panel`) | 1, 2 | Рабочее место сотрудника → Веб-браузер; Nginx | Вход через единый вход банка, статику отдаёт Nginx |
| Мобильное приложение (`mobile_app`) | 14, 15, 16, 18, 28, 29 | Смартфон сотрудника; Nginx | Получает push (APNs / FCM), меняет статус обращения |

Для ЛР № 1–3 по этим контейнерам используйте те же эталоны: L1/L2 — `src/context_l1.puml`, `src/containers_l2.puml`; L3 — `fe_l3.puml`; L4 — классы `web_*` / `mob_*` из глоссария и контракты `docs/packages/contracts/typescript/src`.
