# Контракты событий брокера

Схемы в этой папке описывают формат сообщений, которые ходят через RabbitMQ.
Они используются:

- в Backend API — для валидации при публикации;
- в Воркере разметки и Воркере фоновых задач — для валидации при чтении.

## Правила изменения

1. Схемы версионируются суффиксом в имени файла: `.v1.json`, `.v2.json`.
2. Новая версия создаётся **только при несовместимом изменении**:
   - удаление обязательного поля;
   - переименование поля;
   - сужение `enum`;
   - изменение типа.
3. Совместимые изменения (добавление необязательного поля, расширение `enum`)
   вносятся в текущую версию без повышения номера.
4. При появлении `v2` старая `v1` живёт до тех пор, пока её не перестанут
   читать все потребители.
5. Любое изменение — через PR с ревью владельца затронутого контейнера.

## Очереди

| Очередь | Публикует | Читает | Схема |
|---|---|---|---|
| `reviews.labeling` | Backend API, Воркер фоновых задач | Воркер разметки | `reviews.labeling.v1.json` |
| `cases.events` | Воркер разметки | Воркер фоновых задач | `cases.events.v1.json` |
